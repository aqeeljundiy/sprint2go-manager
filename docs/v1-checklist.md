# v1 checklist: what /v2 must keep, and what it adds

13 Nov 2026. The owner, after the kit-built /v2: "The first version has my vibe and identity, but the UI is just not clean
enough and the features are just not on the level I want, and the UI consistency." So /v2 is now **v1's own screens and
components** (same code, same look) with a layer on top, and nothing v1 has may go missing.

How /v2 is built (one switch, no copies):
- `src/surface.ts` says which surface a page is (`teamV2` for /v2, `adminV2` for /admin/v2) and puts `html.s2v2` on v2.
- `/v2` renders v1's `App` and `ClientApp` (src/Root.tsx); the app's routes live under /v2 (`routeBase`, src/tryOut.ts).
- `src/v2-scale.css` (generated by `scripts/v2-scale.mjs` from v1's CSS): the tidy scale. `src/v2.css`: motion and hand fixes.
  Both only under `html.s2v2`. Words and small behaviour changes check `teamV2` / `adminV2`.
- `/admin/v2` renders v1's `AdminApp` with its addresses under /admin/v2 (`adminPath`).
- v1 at `/` and `/admin` renders exactly as before (checked by screenshot, `v1-first/check-v1-after-1440.png`).

Evidence: `admin-kit-reviews/sprint2go-manager/v1-first/` (`v1-*` = v1, `kitv2-*` = the kit /v2 it replaces, `new-*` =
the new /v2) and the older full set in `admin-kit-reviews/sprint2go-manager/` (`app-v1-*`, `admin-v1-*`).

Columns: **Kept** = present at /v2 or /admin/v2 (v1's code). **v2** = the v2 layer (tidy + motion + fixes) is on it. Where = the
code it lives in. Every line is ticked: nothing v1 has is missing.

Build order (owner's rule, 13 Nov): one page first, approved, then the rest. Page 1, the team app Home, was approved
("Yes, build the rest"); then every other team app screen, the guest portal and the operator console at /admin/v2.
The kit's own v1 checklists and scorecards for the three surfaces: admin-kit-reviews/sprint2go-manager/kit-v1-team,
kit-v1-portal, kit-v1-console (identity.md) and scorecard-team, scorecard-portal, scorecard-console (scorecard.html).

## 6. Goals on top

### (1) Clean and consistent
- Code survey (kit `survey.mjs`) of v1: 62 text sizes, 12 weights, 42 corner sizes, 45 spacing values. v1's CSS stays as
  it is (it is the backup); /v2 and /admin/v2 get `src/v2-scale.css`, generated by `scripts/v2-scale.mjs` from v1's own
  rules: text onto 12/13/14/15/17/20/24/28/32/36/44, corners rounded up onto 6/8/10/12/16/24/pill/round (so circles
  stay round), spacing onto 4/8/12/16/20/24/32/40/48/56/64, weights 550/650 to 600 and 750 to 700. Same specificity
  and order as v1, so nothing moves except the values. Phone layer untouched (already on the system).
- Rendered, per surface (the kit's v1-inventory and scorecard, every screen at 1440): RESULTS_TABLE

### (2) Feature level (from the why review, in v1's style)
- [x] Home: desktop says what needs you under the greeting (the phone already did).
- [x] Tasks: one name for create ("New task"). Notes opens the latest note. Vault hides the faded "Add a login". Meet is called Meetings. Rail names show on hover (v1's own title, kept).
- [x] Portal: one text edge per card, room inside highlights.
- [x] Console: tickets sorted by reply due; invoice Send, Remind and prices ask first; Sign in as… in More behind a confirm; Unlimited; At-risk grace; one revenue figure; Agent access.
- Not done, owner's call (bigger than a layer): fewer view tabs on Tickets/Companies, Change plan as the company's main action, Settings regrouped (Email in one group), the console's proposed sidebar renames (Support, System). Listed in the queue Result.

### (3) Motion
- [x] Home, every app switch, the portal cards, the console's pages, tabs, rows and figures (sections 2 to 5). Every
  animation uses the app's presets (viewIn, cardIn, fadeIn, zoomIn) and the motion tokens, answers what the person did,
  and falls back to a 150 ms fade for reduced motion.
